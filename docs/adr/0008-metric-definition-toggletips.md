# Lighthouse widget metric definitions: per-column toggletips, not a collapsible list

[ADR 0007](0007-trend-toggletip-native-popover.md) kept the Lighthouse Widget's metric-column *definitions* in a `<dl>` glossary behind a `<details>` disclosure ("What do these metrics mean?") under the table, with `aria-describedby` from each `<th>` so the text reached assistive tech even while collapsed. Reading what one column means meant expanding the whole list and scanning for it. This ADR supersedes that half of ADR 0007: the disclosure is removed and each metric column gets its own definition **toggletip** — an `ⓘ` `<button popovertarget>` in the header (and, in the mobile card layout, in each cell) that opens the definition in a native HTML Popover element, opened on click/tap/Enter, dismissed on Escape or outside click, with **zero JavaScript**. The seven definition panels live once at the end of the widget and keep the `lh-def-*` ids, so every `<th>`'s `aria-describedby` still resolves. ADR 0007's trend-arrow toggletip and its progressive-enhancement stance are unchanged; only the definitions move.

## Considered options

- **Hover to open the definition** (the original request) — rejected: the Popover API has no declarative hover trigger (`popovertarget` fires on click only), so hover-to-open needs JavaScript, which the repo's standards push back on; and a hover-only tooltip is unreachable on touch and fails WCAG 2.1 SC 1.4.13. ADR 0007 rejected hover for the trend arrows for the same reasons.
- **Pure CSS `:hover`/`:focus-within` tooltip, no Popover API** — rejected: the table scrolls horizontally on narrow screens (`.lighthouse-table-scroll`), and a scroll container clips any absolutely-positioned bubble that escapes the cell. Same rejection as ADR 0007.
- **Keep the `<details>` glossary and add the toggletips alongside it** — rejected: two ways to read the same text, and the definition strings would then live in two places to keep in sync. The glossary's one advantage — a browsable all-in-one list — was judged not worth that cost.
- **One shared popover reused for every column** — not possible: a popover holds one column's text, and seven columns need seven strings. Seven popover elements, many trigger buttons pointing at them by id.

## Consequences

- **No more browse-all view.** The `<details>` glossary let a reader see all seven definitions at once, `Ctrl-F` them, or link to the section. Per-column toggletips replace that with proximity — the definition is at the column header — but there is no single list anymore.
- **Definitions don't appear in print.** A popover is `display: none` until invoked, so the About page's printed output carries no definitions. Not a regression: a closed `<details>` didn't print its contents either, and ADR 0007 deliberately scopes print rules to the Resume page.
- **Seven `ⓘ` glyphs in the compact header row.** The header row (kept deliberately compact, guntherjh/guntherjh.github.io#41) gains a small muted glyph per column. Same trade-off ADR 0007 accepted for the trend arrows.
- **Trigger count differs by layout.** Desktop shows one `ⓘ` per column — seven, in the header. The mobile card layout has no visible column header, so the `ⓘ` moves into each cell: four page cards times seven metrics is 28 triggers (one per metric per card). The header and cell copies are `display: none`-swapped at the 640px breakpoint (not merely visually hidden), so only one set is ever active and the hidden `<thead>` contributes no dead tab stop.
- **Each metric `<th>` gets an `aria-labelledby`** pointing at a span around its own short label ("Perf", "LCP", …). Without it, the nested `ⓘ` button's accessible name folds into the header cell's name and screen readers announce "Perf, Performance — what this column measures, button" as the column context on every data cell. The `aria-labelledby` looks redundant but isn't — don't remove it while the button is a child of the `<th>`.
- **The panel is collocated with its `ⓘ` where CSS anchor positioning is supported** (`@supports (position-area: top)`), tethered to the invoking button as its implicit popover anchor. This revises the grilling session's choice to reuse ADR 0007's untethered bottom-of-viewport panel verbatim — with several `ⓘ` triggers now scattered across the table rather than one arrow per changed cell, a panel pinned to the bottom of the screen was too far from what opened it. Browsers without anchor positioning (Firefox, at time of writing) keep the bottom-centered fallback, which is why each panel still self-identifies. Scoped to the definition panels; ADR 0007's trend panels are unchanged.
- **Browsers without Popover API support** render the `ⓘ` button inert (no panel); screen readers still get the full definition via `aria-describedby` on both the `<th>` and the button. Same accepted progressive enhancement as ADR 0007.

Metric definitions and thresholds are sourced in [docs/research/lighthouse-metric-definitions.md](../research/lighthouse-metric-definitions.md). guntherjh/guntherjh.github.io#138.
