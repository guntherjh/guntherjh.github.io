# Bounded run history in the Lighthouse Snapshot, not a single most-recent run

The Lighthouse Widget originally showed only the most recent audit, with no way to tell whether a score had improved or regressed since the last run (guntherjh/guntherjh.github.io#71). We changed `src/_data/lighthouse.json`'s shape from a single `{ capturedAt, pages }` Snapshot to `{ history: [{ capturedAt, pages }, ...] }`, newest run first, with `scripts/lighthouse-audit.mjs` prepending each new run and trimming to the last 10 — long enough to be a real trend window given audits run per merge to `master`, short enough that the committed JSON file doesn't grow unbounded over the site's lifetime. We considered keeping history unbounded (rejected: a git-tracked file that only ever grows) and a separate history file alongside the existing one (rejected: no other consumer needs the split, and it's one more path to keep in sync). The widget itself only surfaces a comparison against the immediately-previous run (`history[1]`), not a multi-point sparkline across the full retained window — a deliberate scope cut to stay within the compact-table constraint from #41, not an oversight; the full history is retained regardless, so a deeper trend view remains possible later without another data-shape change. That comparison is between each run's classified `good`/`average`/`poor` level (see `eleventy.config.js`'s `scoreLevel`/`metricLevel`), not the raw score/metric delta — real committed Snapshot history shows the same metric swinging by lab/network noise alone as much as a genuine regression would (e.g. Home's Performance score across recent runs: 100, 90, 100, 85, 88 with no code changes involved), so a raw-delta comparison would flag noise as a real change on nearly every run. Comparing levels instead reports only an actual tier change, at the cost of not surfacing smaller-magnitude real changes that stay within the same tier. A pre-existing Snapshot in the old shape (no `history` key) is treated as having no history rather than migrated in code — the real committed file was migrated directly as part of this change instead.
